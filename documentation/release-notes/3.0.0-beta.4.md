# 3.0.0-beta.4

Fourth prerelease of 3.0. `TimeWarp.Amuru` and `TimeWarp.Amuru.Tools` ship together at `3.0.0-beta.4` (one `<Version>` in `source/Directory.Build.props`). This note records the move to .NET 11 GA, a dependency refresh, and the githook self-pin move. It is not a NuGet publish.

No behavior change. The public symbol surface stays the `3.0.0-beta.3` surface. Both `PublicAPI.Unshipped.txt` files stay header-only.

## .NET 11 GA

`global.json` moves from the `11.0.100-rc.3.26522.148` SDK to the `11.0.100` GA SDK (`allowPrerelease: false`, `rollForward: latestFeature`). `Microsoft.CodeAnalysis.NetAnalyzers` follows it to `11.0.100`, so the analyzer and the SDK band still match.

`Microsoft.Extensions.Hosting` moves to `11.0.0`, the stable .NET 11 build the `3.0.0-beta.3` note was waiting for. It is used only by the MCP stdio validation server under tests and does not enter the shipped graph.

### NuGet.Versioning 8.0.0 (major)

`TimeWarp.Amuru.Tools` depends on `NuGet.Versioning` directly, so consumers of the tools package now resolve `8.0.0`. No NuGet 8.0 release-note page was found at the time of this change. The package itself shows the change: the `lib/net8.0` asset is replaced by `lib/net10.0` (`net472` stays). Amuru.Tools targets `net11.0` and uses only `NuGetVersion.TryParse` and version comparison. That code compiles unchanged, and the version-comparison tests pass. A consumer that pins `NuGet.Versioning` below `8.0.0` gets a NuGet downgrade error and must raise its pin.

### TimeWarp.Build.Tasks 2.0.1-beta.1

The stable `2.0.0` cannot be used. `TimeWarp.Nuru` `4.0.0-beta.14` declares `TimeWarp.Build.Tasks >= 2.0.1-beta.1`, and the `2.0.0` pin fails restore of the dev CLI with NU1605 (package downgrade). The pin is the newest listed build, `2.0.1-beta.1`. Build.Tasks is dev-only (`PrivateAssets="all"`). Both `3.0.0-beta.4` nuspecs match the published `3.0.0-beta.3` nuspecs except for version, commit, and dependency versions. The package file lists are the same.

### TimeWarp.SourceGenerators 1.0.0-beta.16

This version adds TWA0004 (`#region Purpose` in every file) and TWA0038 (500-line file limit). `run-tests.cs` gains its Purpose region. The 14 files already recorded in `.timewarp/line-cap-baseline.json` (the shrink-only ratchet that the `source-file-line-cap` audit holds) each get a `dotnet_diagnostic.TWA0038.max_lines` entry in `.editorconfig` set to the file's current length. A baselined file that grows fails the build. Every other file keeps the 500-line limit.

### TimeWarp.Jaribu 1.0.0-beta.16

`TestHelpers.TestSkipped(string)` is now `TestSkipped(ITerminal, string)`. The six skip sites in the core tests pass `TimeWarpTerminal.Default`.

### TimeWarp.Nuru 4.0.0-beta.14

The dev CLI compiles unchanged and `dev --capabilities` lists the same eight commands.

## Githook self pins

`TimeWarp.Amuru` and `TimeWarp.Amuru.Tools` in `Directory.Packages.props` move from `3.0.0-beta.2` to the published `3.0.0-beta.3`. The five `.githooks` runfiles consume those pins through central package management and compile against them.

## Unchanged

- CliWrap stays the process library for ordinary commands. The JSON-RPC child uses the .NET 11 handle APIs.
- A child that exits during the timeout grace period still reports its own exit code and `TimedOut` false. A grace-period kill is still exit 124.
- No public members were added or removed.
